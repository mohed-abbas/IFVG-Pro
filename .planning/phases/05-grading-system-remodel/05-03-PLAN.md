To compute the individual scores for display, re-derive them from the IFVG fields. This avoids storing 5 extra int fields on the IFVG type. The scoring functions already exist from Plan 02:

```
// Recompute scores for tooltip display
int tt_sweep_delivery = (ifvg.has_sweep and ifvg.has_delivery) ? 2 : ((ifvg.has_sweep or ifvg.has_delivery) ? 1 : 0)
// For momentum, map string back to int
int tt_momentum = ifvg.momentum == "strong_no_chop" ? 2 : (ifvg.momentum == "weak_or_choppy" ? 0 : 1)
int tt_target = score_target_clarity(ifvg.dol)
// For singularity, we need FVG size — use (ifvg.top - ifvg.bottom)
float tt_fvg_size = ifvg.top - ifvg.bottom
bool tt_singular = true  // Default: assume singular at render time (singularity was checked at inversion)
int tt_singular_score = not na(atr_value) and tt_fvg_size >= atr_value * 0.5 ? 2 : 1
// NOTE: We can't re-check is_fvg_singular() at render time since the source FVG is gone.
// The IFVG grade already reflects singularity. For tooltip, show size-based heuristic.
// If grade is C or B-, singularity was likely 0. Use grade as proxy:
// Actually, a simpler approach: store singularity score on IFVG. But to avoid adding more fields,
// we'll show a simplified version.
int tt_pd = score_pd_zone(ifvg.pd_zone, ifvg.is_bullish)
int tt_total = tt_sweep_delivery + tt_momentum + tt_target + tt_singular_score + tt_pd
```

WAIT — this approach has a problem. We can't reliably reconstruct the singularity score at render time because is_fvg_singular() depends on the FVG array state at inversion time (not render time). 

Better approach: Add a `int singularity_score` field to the IFVG type and store it at inversion time. This is a small addition (1 field) that avoids lossy reconstruction.

**Step 1:** Add `int singularity_score` field to IFVG type (after `pd_zone`, before `box_id`):
```
    int singularity_score  // 0=not singular, 1=singular small, 2=singular obvious
```

**Step 2:** Update LTF IFVG.new() in check_inversions() to compute and store it:
```
int singular_score = score_singularity(fvg_singular, fvg_size, atr_value)
```
And in IFVG.new(): `singularity_score = singular_score`

**Step 3:** Update HTF IFVG.new(): `singularity_score = 0` (HTF IFVGs not graded)

**Step 4:** Now build the tooltip using stored values:

```
// Build tooltip with 5-criterion scoring breakdown
int tt_sd = (ifvg.has_sweep and ifvg.has_delivery) ? 2 : ((ifvg.has_sweep or ifvg.has_delivery) ? 1 : 0)
int tt_mom = ifvg.momentum == "strong_no_chop" ? 2 : (ifvg.momentum == "weak_or_choppy" ? 0 : 1)
int tt_tgt = score_target_clarity(ifvg.dol)
int tt_sg = ifvg.singularity_score
int tt_pd = score_pd_zone(ifvg.pd_zone, ifvg.is_bullish)
int tt_total = tt_sd + tt_mom + tt_tgt + tt_sg + tt_pd
string sd_detail = ifvg.has_sweep and ifvg.has_delivery ? "Sweep+Delivery" : (ifvg.has_sweep ? "Sweep only" : (ifvg.has_delivery ? "Delivery only" : "Neither"))
string mom_text = ifvg.momentum == "strong_no_chop" ? "Strong" : (ifvg.momentum == "weak_or_choppy" ? "Weak" : "Moderate")
string dol_text = not na(ifvg.dol) ? (ifvg.dol.liq_type + " @ " + str.tostring(ifvg.dol.level, format.mintick)) : "None"
string zone_text = str.upper(ifvg.pd_zone)
entry_status = ifvg.entry_valid ? "VALID" : "INVALID"
tooltip_text = "Grade: " + ifvg.grade + " (" + str.tostring(tt_total) + "/10)\n" +
              "─────────────\n" +
              "[" + str.tostring(tt_sd) + "] " + sd_detail + "\n" +
              "[" + str.tostring(tt_mom) + "] Momentum: " + mom_text + "\n" +
              "[" + str.tostring(tt_tgt) + "] Target: " + dol_text + "\n" +
              "[" + str.tostring(tt_sg) + "] Singularity\n" +
              "[" + str.tostring(tt_pd) + "] Zone: " + zone_text + "\n" +
              "─────────────\n" +
              "Entry: " + entry_status
```

This produces a tooltip like:
```
Grade: A (8/10)
─────────────
[2] Sweep+Delivery
[2] Momentum: Strong
[1] Target: EQL @ 4150.25
[2] Singularity
[1] Zone: NEUTRAL
─────────────
Entry: VALID
```

Concise format per Research Pitfall 6 — uses `[N]` prefix instead of verbose "Score N/2".

Pine Script v6: All string concatenation lines must end with `+` as the last token before newline (for multi-line string building). No blank lines inside the if block containing this tooltip code.
