**1. score_target_clarity(Liquidity dol_target) => int**

Scores DOL target quality 0-2 per D-05 criterion 3:
- Score 2 (clear DOL): `not na(dol_target)` AND (`dol_target.quality == "perfect"` OR `dol_target.touch_count >= 2`)
- Score 1 (weak target): `not na(dol_target)` but does not meet score-2 criteria (single-touch relative quality level)
- Score 0 (no target): `na(dol_target)` — find_dol() returned nothing

```
score_target_clarity(Liquidity dol_target) =>
    int result = 0
    if not na(dol_target)
        if dol_target.quality == "perfect" or dol_target.touch_count >= 2
            result := 2
        else
            result := 1
    result
```

**2. score_singularity(bool is_singular, float fvg_size, float atr_val) => int**

Scores FVG singularity 0-2 per D-05 criterion 4:
- Score 2 (singular and obvious): `is_singular == true` AND `fvg_size >= atr_val * 0.5` (large, visually obvious gap)
- Score 1 (singular but not obvious): `is_singular == true` AND `fvg_size < atr_val * 0.5` (singular but small/inconspicuous)
- Score 0 (not singular): `is_singular == false`

```
score_singularity(bool is_singular, float fvg_size, float atr_val) =>
    int result = 0
    if is_singular
        if not na(atr_val) and fvg_size >= atr_val * 0.5
            result := 2
        else
            result := 1
    result
```

**3. score_pd_zone(string pd_zone, bool ifvg_is_bullish) => int**

Scores PD zone positioning 0-2 per D-09:
- Score 2 (correct zone): bullish IFVG in "discount" OR bearish IFVG in "premium"
- Score 1 (neutral): pd_zone is "equilibrium" or "neutral" (including when no dealing range detected)
- Score 0 (wrong zone): bullish IFVG in "premium" OR bearish IFVG in "discount"

```
score_pd_zone(string pd_zone, bool ifvg_is_bullish) =>
    int result = 1  // default neutral
    if pd_zone == "discount"
        result := ifvg_is_bullish ? 2 : 0
    else if pd_zone == "premium"
        result := ifvg_is_bullish ? 0 : 2
    // "equilibrium" and "neutral" stay at 1
    result
```

NOTE: Until Phase 2 re-implements PD zone detection, pd_zone is always "neutral" so score_pd_zone always returns 1. This means A+ is unreachable via the hard gate (D-06 requires pd_score=2). This is correct and expected.

**Part A: Rewrite calculate_grade()**

Replace the entire calculate_grade() function body. New signature:

```
calculate_grade(bool has_sweep, bool has_delivery, int momentum_score, Liquidity dol_target, bool fvg_singular, float fvg_size, string pd_zone, bool ifvg_is_bullish) =>
```

Returns `string` — the grade ("A+", "A", "A-", "B+", "B", "B-", "C").

Implementation:

```
calculate_grade(bool has_sweep, bool has_delivery, int momentum_score, Liquidity dol_target, bool fvg_singular, float fvg_size, string pd_zone, bool ifvg_is_bullish) =>
    // ── Criterion 1: Sweep + Delivery (0-2) per D-05 ──
    int sweep_delivery_score = 0
    if has_sweep and has_delivery
        sweep_delivery_score := 2
    else if has_sweep or has_delivery
        sweep_delivery_score := 1
    // ── Criterion 2: Momentum (0-2) — already scored by assess_momentum() ──
    // momentum_score is 0, 1, or 2 directly
    // ── Criterion 3: Target Clarity (0-2) ──
    int target_score = score_target_clarity(dol_target)
    // ── Criterion 4: FVG Singularity (0-2) ──
    int singular_score = score_singularity(fvg_singular, fvg_size, atr_value)
    // ── Criterion 5: PD Zone (0-2) per D-09 ──
    int pd_score = score_pd_zone(pd_zone, ifvg_is_bullish)
    // ── Total Score (0-10) ──
    int total = sweep_delivery_score + momentum_score + target_score + singular_score + pd_score
    // ── Grade Mapping per D-05, D-07 ──
    string result = "C"
    // A+ hard gates per D-06: sweep_delivery=2 AND pd_score=2 AND total>=9
    if total >= 9 and sweep_delivery_score == 2 and pd_score == 2
        result := "A+"
    else if total >= 7
        result := total >= 9 ? "A" : (total >= 8 ? "A" : "A")
    else if total == 6
        result := "A-"
    else if total == 5
        result := "B+"
    else if total >= 3
        result := "B"
    else if total == 2
        result := "B-"
    // else total 0-1 stays "C"
    result
```

Wait — simplify the total >= 7 branch. The mapping is:
- A+ = 9-10 (only if hard gates pass, otherwise cap at A)
- A = 7-8 (or 9-10 if hard gates fail)
- A- = 6
- B+ = 5
- B = 3-4
- B- = 2
- C = 0-1

Correct implementation:

```
    string result = "C"
    if total >= 9 and sweep_delivery_score == 2 and pd_score == 2
        result := "A+"
    else if total >= 7
        result := "A"
    else if total == 6
        result := "A-"
    else if total == 5
        result := "B+"
    else if total >= 3
        result := "B"
    else if total == 2
        result := "B-"
    result
```

This correctly handles D-06: if total is 9-10 but hard gates fail, falls through to `total >= 7` which gives "A" (capped at A, not A+).
